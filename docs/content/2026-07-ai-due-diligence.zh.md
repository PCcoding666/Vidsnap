# 我让 AI 给自己的项目做尽调,它发现我的文档在撒谎

> 状态:草稿 v1(供发布:掘金 / 即刻 / 知乎)· 配图位已标注 · 英文版见同目录 `.en.md`

---

我给 AI 发了一份"技术尽职调查"提示词,让它审计我自己的开源项目。几个小时后它交回来一张表,标题是:**"声称 vs 实际"**。

五行。每一行,都是我的文档在对我撒谎。

## 背景

项目叫 [VidSnap](https://github.com/PCcoding666/Vidsnap):上传本地视频、写一句自然语言目标,系统把视频变成可搜索、可引用的文本资产(转录/摘要/图文笔记/问答)。典型的"一个人 + AI 结对"项目——功能迭代很快,快到文档、注释、甚至代码里的自我声明,全都跟不上了。

我本来只想问 AI 一个问题:"下一步该投入什么?"但我没有直接要建议,而是要求它先走完一个六阶段流程:

```
1. 建立项目事实模型(只陈述,不评价)
2. 能力盘点(每项能力必须给出代码/文档/commit 证据)
3. Gap 分析
4. 机会分析(Quick wins / 高杠杆 / 该删的)
5. Roadmap
6. 决策(一周时间,做什么不做什么)

铁律:不许凭印象;所有结论标注 Confirmed / Likely / Unknown;
证据不足就写 Unknown,不许编。
```

## 它发现的谎言

<!-- 配图位:「声称 vs 实际」对照表截图 -->

| # | 文档/注释声称 | 代码实际 | 证据 |
|---|---|---|---|
| 1 | "关键帧/视觉分析已禁用,纯文本处理" | 帧分析**默认开启**,而且是最有差异化的功能(截帧+VLM看图+OCR 图文笔记) | `config.py` 里 `WORKSPACE_FRAMES_ENABLED=true` |
| 2 | planner 对外宣称 "YouTube 下载超出范围" | `/jobs` 接口**真的会下载 YouTube** | `planner_service.py:198` vs `workspace.py:104` |
| 3 | "住宅 IP 基本不反爬,这只是一层薄封装" | 实际必须 Deno + bgutil PO Token + cookie **三件套缺一不可** | 注释 vs README 自己写的前置要求 |
| 4 | requirements 注释:"使用 SenseVoice 转录" | 实际调用的是另一个 ASR 模型 | `pipeline_service.py:30` |
| 5 | "Supabase 已禁用" | 前端仍打包 supabase 客户端,**里面硬编码着已泄露的 anon key** | `frontend/.env.production`(被 git 跟踪) |

最讽刺的是第 2 条:planner 每次生成计划,都会向用户输出一句写死的"我不做 YouTube"——与此同时,同一个系统正在下载 YouTube。**系统自己打自己的脸,而我毫无察觉。**

## 根因不是懒,是一种架构病

AI 的诊断比我预期深一层。它说这五条不是五个孤立的笔误,是**同一个模式的五个症状**:

> 把"能力/边界/步骤"声明成静态数据(计划、注册表、注释),而真正的执行走另一条硬编码路径,两者之间只靠字符串约定松耦合。声明和执行分头演化,文档漂移只是时间问题。

换句话说:**文档撒谎是果,声明与执行没有单一事实源才是因。** 你的项目里大概率也有这个病——每一句"XX 已禁用/不支持"的注释,都值得怀疑。

## 修复:让 AI 自己把谎言清干净

我把修复做成了一个带铁律的自主 backlog,交回给 AI 执行:

- **证据优先**:动手前先读代码确认现状,区分 Confirmed/Unknown
- **最小安全增量**:一次一个可独立验证的改动
- **绝不弄坏构建**:每次改完必须全量测试 + 构建
- **门控**:扩产品边界的事必须停下来问我

它逐条修完:声明对齐、删掉两千多行死代码、把泄露的 key 从工作树清掉、把"帧分析"改造成显式的 `visual_mode` 可选项、CI 落地。48 个测试、120 条 planner golden case 全绿。

## 然后,修复自己也撒了一次谎

高潮在这里。修复过程中,ASR 模型名按我的口述统一成了 `fun-asr-flash`。测试全绿、CI 全绿、文档一致——完美。

然后我上传了一个**真实视频**验收。转录当场报错:

```
HTTP 400 - Model not exist.
```

`fun-asr-flash` 这个模型**根本不存在**。所有静态检查都拦不住它,因为它在每一层都"自洽"——只有真实世界不配合。AI 随后直接探测了 ASR 服务商的 API,确认有效模型列表,改回正确的 id,再用真实视频端到端跑通:69 段转录、一份带时间戳引用的结构化笔记。

这给了我这次尽调最重要的一条纪律:

> **声明必须被真实样例验证过,才算数。** 测试绿 ≠ 真的能跑。

## 现在的状态:敢公开成绩单

修复完成后,我把两件事做成了公开的:

1. README 顶部挂了一枚**实时徽章**:每次 push,CI 自动重跑 120 条 planner golden case 并公布通过率。敢挂,是因为数字是 CI 算的,不是我说的。
2. 整个修复过程写进了公开的 [构建日志](https://github.com/PCcoding666/Vidsnap/blob/vidsnap_slim/docs/build-log.md)——包括 AI 翻车的那一次。

这就是我现在给这个项目的定位:**glass-box AI**——透明(执行 trace 可视化)、可审计(产物带时间戳引用)、可复现(成绩单公开)。工具如此,开发过程也如此。

## 你可以直接抄走的东西

1. **那份尽调 prompt 骨架**(上文六阶段 + 铁律),对任何"迭代快过文档"的项目都适用
2. **三条纪律**:证据优先 / 三级置信标注 / 真实样例验收
3. **一个警惕**:去搜一下你仓库里所有写着"已禁用""不支持""out of scope"的地方——挨个验证,大概率至少有一条在撒谎
