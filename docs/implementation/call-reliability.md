# 调用失败时，仍然能看懂发生了什么

本批只补调用可靠性，不更换模型、不增加工具、不改变默认取证顺序，
不增加网络失败后的自动重试；现有 Agentic 格式修复规则保持不变。
离线测试通过不代表真实视频的回答质量已经改善。

## 时间限制

- Qwen 的 `timeout_seconds` 默认仍为 120 秒，现在同时限制一次请求的整体等待：
  包括等待并发名额、连接、发送和读取响应。HTTP 客户端原有的分阶段超时仍保留。
- Harness 的 `max_wall_seconds` 不再只在步骤之间检查。到时会取消正在等待的
  探测、工具或模型调用，以 `EXHAUSTED` 结束，原因为 `wall-clock budget exceeded`。
- 主动取消仍记为 `FAILED` / `cancelled`，不会误标为预算耗尽。
- 主动取消后先解除总时限定时器，再等待清理完成。重复取消不会跳过请求或
  子进程的清理；取消与响应同时到达时，也不能把取消误记成成功。
- 取消 FFmpeg / ffprobe 后会终止并回收子进程；此前完成并保存的证据不会删除。
- 这些是协作式取消：清理资源可能需要额外时间，不能强制打断堵塞事件循环的
  同步代码或拒绝响应取消的第三方插件。不是操作系统级的强制截止。

## 在轨迹中查看失败

失败事件增加 `payload.failure`，使用独立版本 `vidsnap.provider-failure/v1`；
原有事件类型、终态和简短失败原因保持兼容。

`category` 只允许固定类别：连接/读取/发送/连接池超时、连接错误、传输错误、
HTTP 错误、请求总时限、响应格式错误、主动取消、运行总时限及其他 provider 错误。
HTTP 错误可以记录状态码；不会记录原始异常、请求、响应、地址、密钥或鉴权头。

`input_bytes` 是客户端已构造请求体的字节数，不是确认被服务端接收的字节数。
尚未取得并发名额时该值为 `null`；已经构造请求后发生网络错误，保留已测到的大小。
`input_tokens` / `output_tokens` 仅在响应包含有效计数时记录，缺失为 `null`，
不能把它当成零成本。HTTP 错误或响应格式不合要求，但附有用量时，
只提取通过校验的数字计数，不保存响应原文。

旧版 `usage` 数字字段继续兼容：缺失计数可能仍显示 0，
必须结合 `provider_reported=false` 和上述可空字段判断，不能把 0 当作实测。
`model_calls` 计数的是 provider 调用尝试，包括等待名额后失败的尝试，
并不证明服务端收到了请求。报告比较时需注明这一口径。

## 验证范围

新增测试使用合成媒体和离线 HTTP 响应，覆盖三类 Qwen 调用、失败计量、
并发等待、总时限、主动取消、证据保留与子进程清理。
没有运行付费视频分析，也没有覆盖或改写此前的真实运行结果。
