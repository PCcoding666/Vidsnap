# 当前默认工具与数据入口审阅清单

本清单用于用户审阅，只描述当前事实与待决问题，不预先新增任何能力。本次发布未启用任何新工具或新数据入口。

## 当前默认内置工具

当前默认内置工具：transcribe_audio、sample_evidence。

### transcribe_audio

- 作用：对内核管理的本地音频做有界 ASR，产出带时间戳的转录证据；未指定窗口时覆盖已探测到的完整时长。
- 边界：最多接受 3 个时间窗口，且窗口必须落在已探测的媒体时长内；只读取本地媒体，不接受路径、URL 或任何网络输入；结果写入 RunBundle evidence。提取出的音频会随 ASR 请求发送到固定配置的 Qwen 端点（见“本地输入选择与出站模型处理”）。

### sample_evidence

- 作用：在请求的时间窗口内做确定性的本地帧采样，产出视觉证据供综合与验证环节引用。
- 边界：最多 3 个时间窗口，单次采样上限 96 帧并受全局帧预算约束；参数不接受路径、URL 或编码器选项；采样对象始终是内核已登记的本地视频。选出的帧会作为模型请求内容发送到固定配置的 Qwen 端点（见“本地输入选择与出站模型处理”）。

Fixed 模式按 transcribe_audio 先于 sample_evidence（先语音后视觉）的固定顺序执行；Agentic 模式下由模型在预算内自选调用顺序，但只能调用这两个已允许的工具。

## 本地输入选择与出站模型处理

并非所有处理都在本地完成。工具的输入选择发生在本地，但根据配置的 Qwen 端口与路径，以下内容可随请求发送到固定配置的 Qwen 端点：

- transcribe_audio 提取的音频，以 Base64 形式包含在 ASR 请求中；
- sample_evidence 选出的视觉帧；
- 调用方登记的可用本地字幕；
- 用户提交的问题证据。

插件工具本身不能选择 URL、模型或提供商；出站端点由固定配置决定，本清单不改变任何运行时能力。

原始媒体默认不会写入 git，也不会包含在 trace 导出中。提供商的数据留存、区域与隐私条款需要用户自行审阅后再决定是否接受上述出站数据传输。

## 当前可选数据入口

当前可选数据入口：本地视频、可用本地字幕、外部 benchmark manifest、RunBundle evidence/trace metadata。

### 本地视频

- 作用：每次运行的必需输入，经 ffprobe 探测后作为全部证据的来源。
- 边界：必须是本地绝对路径；不下载、不转存任何远程媒体。

### 可用本地字幕

- 作用：当调用方登记了本地字幕文本时，作为补充证据参与综合分析。
- 边界：只接受调用方显式提供的本地内容；不会自动发现、下载或解析来源不明的字幕。

### 外部 benchmark manifest

- 作用：预注册的公开案例选择清单（含哈希绑定），用于可复现的 benchmark 运行。
- 边界：manifest 在仓库之外准备；案例媒体仍需位于本地，manifest 本身不能引入网络数据。

### RunBundle evidence/trace metadata

- 作用：历史本地运行的只读证据与 trace 元数据，可用 `vidsnap trace export` 离线查看。
- 边界：只读取 RunBundle 内已存在的内容；旧版结果目录是 summary-only，永远不会被重建或补造步骤。

## 审阅问题

1. 默认与可选分类：以上工具与数据入口中，哪些应保持默认，哪些应降级为可选或移出？分类依据是什么？
2. 隐私与许可：每个数据入口在隐私（人脸、语音、字幕中的个人信息）与素材许可方面需要满足什么条件才能进入默认路径？
3. 成本：每个入口的本地计算成本、模型调用成本与存储成本是否在 12 次模型调用、6 次工具调用、96 帧、900 秒的默认预算内可接受？
4. OCR 与 scene metadata 是否应做成插件：若需要画面文字或镜头切分信息，OCR 与 scene metadata 是否应实现为独立插件（而非默认工具）？其证据模态、预算占用与验证规则如何定义？

## 候选扩展（均未启用）

以下仅为供审阅的候选项，全部保持未启用状态；启用前必须先完成上述审阅并更新 conformance 门槛。

- OCR 文本提取插件 (not enabled)：从本地帧中提取画面文字，作为 `ocr` 模态证据；待审阅隐私与许可影响。
- scene metadata 插件 (not enabled)：产出镜头边界等结构化元数据，作为 `scene` 模态证据；待审阅成本与验证规则。
